## Remediation Details

### C1 — Verified JWT Authentication (RESOLVED)

**Root cause:** Identity was derived from `x-user-role` / `x-user-id` HTTP headers — any caller could impersonate any role.

**Fix:**
- `jsonwebtoken` + `bcryptjs` added as server dependencies
- `POST /api/auth/login` verifies bcrypt password hash against the database; on success issues a signed HS256 JWT embedded in an HTTP-only cookie
- `GET /api/auth/me` / `POST /api/auth/logout` manage the session lifecycle
- `authenticate` middleware (new) verifies the JWT cookie on every protected request and sets `req.user = { userId, role, org }` from the verified payload
- Applied globally to all `/api/*` routes, exempting only `/api/healthz` and `/api/auth/*`
- `getUserId(req)` and `getValidatedRole(req)` in `route-helpers.ts` now read exclusively from `req.user`
- `getUserOrg(req)` in `governance.ts` reads from `req.user.org` (JWT), not the header
- **Defense-in-depth:** A global middleware strips `x-user-role`, `x-user-id`, `x-user-org` from all incoming requests *before* route handlers run. The `authenticate` middleware then re-injects these headers from the verified JWT payload, so the 30+ legacy route files that still read those headers continue to work correctly — but now receive the server-verified values, not any caller-supplied ones

**Files changed:** `src/lib/jwt.ts` (new), `src/middlewares/authenticate.ts` (new), `src/routes/auth.ts` (new), `src/middlewares/roleAuth.ts`, `src/lib/route-helpers.ts`, `src/routes/governance.ts`, `src/middlewares/auditLog.ts`, `src/app.ts`

### C2 — Session Management (RESOLVED)

**Root cause:** `SESSION_SECRET` was set but no session management existed.

**Fix:**
- HTTP-only cookie named `marsad_session` containing a signed JWT
- Cookie attributes: `httpOnly: true`, `sameSite: 'strict'`, `secure: true` (in production), `maxAge: 8h`, `path: '/'`
- `SameSite=Strict` provides CSRF protection (cross-site requests cannot send the cookie)
- `httpOnly` prevents JavaScript (XSS) from reading the token
- Token expiry: 8 hours (one working day)
- Logout explicitly calls `res.clearCookie()` — confirmed in T16/T17

### C3 — CORS No-Origin Bypass (RESOLVED)

**Root cause:** `if (!origin) return cb(null, true)` unconditionally allowed all no-origin requests (curl, scripts). CORS errors returned HTTP 500.

**Fix:**
- In production: a middleware runs before all routes and returns `403` for any request missing an `Origin` header (except `/api/healthz`)
- In development: no-origin allowed (preserves curl/shell debugging workflow)
- CORS rejections: `cb(new Error("CORS_REJECTED"))` now triggers the error handler which returns `403`, not `500` — confirmed in T14

### H1 — Trust Proxy (RESOLVED, bonus fix)

`app.set("trust proxy", 1)` added so `X-Forwarded-For` is correctly read and the real client IP is used for rate limiting.

## Beta Feedback Authorization — Final Verification

Conducted 7 July 2026. Instruments the full middleware chain with a `res.json` stack interceptor (`TRACE_4XX=1`) against the broken router order, then confirms all four access patterns after the fix.

### Root-cause trace

```
━━━ TRACE_4XX ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  method : POST
  path   : /beta/feedback
  status : 403
  user   : {"userId":8,"role":"citizen","org":""}
  body   : {"error":"Insufficient permissions for this action."}
  stack  :
    at <anonymous>
       artifacts/api-server/src/middlewares/roleAuth.ts : 25 : 23
    at Layer.handleRequest   router@2.2.0/lib/layer.js:152
    at trimPrefix            router@2.2.0/index.js:342
    at next                  router@2.2.0/index.js:291
    at router41.handle       router@2.2.0/index.js:186
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

**Exact line:** `roleAuth.ts:25` — `res.status(403).json(...)` inside the `requireRole` anonymous closure, fired by the `!allowedRoles.includes(role)` check.

### Why it fired before `/beta/*` was reached

Three routers register `requireAnyRole` with **no path argument** (method: catch-all):

| Source file | Line | Compiled var |
|---|---|---|
| `src/routes/workspace.ts` | 41 | `router31` |
| `src/routes/adkg.ts` | 43 | `router32` |
| `src/routes/kb.ts` | 32 | `router33` |

```ts
router.use(requireAnyRole);  // no path — intercepts every request dispatched to this router
```

In the original `routes/index.ts` registration order, `workspaceRouter` was mounted **before** `betaRouter`. When citizen posted to `/api/beta/feedback`, Express dispatched through the index router in order. `workspaceRouter` ran first, its `router.use(requireAnyRole)` fired for path `/beta/feedback` (no route in workspace matches it, but the middleware runs regardless), the `requireAnyRole` check rejected `citizen` (excluded from all 13 professional roles), and returned 403. The response was committed. `betaRouter` never ran.

### Fix

`betaRouter` moved to register **before** the three routers carrying the global guard in `routes/index.ts`:

```ts
router.use(betaRouter);       // ← reaches citizen before any guard fires
router.use(workspaceRouter);  // requireAnyRole lives here
router.use(adkgRouter);       // requireAnyRole lives here
router.use(kbRouter);         // requireAnyRole lives here
```
