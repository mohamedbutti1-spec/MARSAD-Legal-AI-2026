How we achieved 120ms finality across 38 chains

Amara Chen · Jul 18, 2026 · 8 min read

Eighteen months ago, a cross-chain transaction through BUIO took an average of 780ms to finalize. Today it takes 120ms — a 6x improvement — without weakening a single security assumption. This is the story of how we got there.

The bottleneck

Our original relayer network polled each connected chain independently, batching proofs every 400ms to control cost. That batching window was the single biggest contributor to latency, and it scaled linearly with the number of chains we supported.

As we crossed 20 integrated networks, the math stopped working: more chains meant more batches, and more batches meant users waiting longer for the same guarantee.

Rethinking consensus

Instead of batching proofs per chain, we moved to a shared aggregation layer that collects attestations from all relayers into a single Merkle root every 90ms, regardless of how many chains are attached.

The insight wasn't a faster algorithm — it was decoupling proof aggregation from the number of chains entirely.

This required rewriting our light-client verification logic so that any chain could confirm inclusion using the shared root instead of a chain-specific proof:

function verifyInclusion(leaf, proof, root) {
  return merkleVerify(leaf, proof, root);
}

What changed for developers

Nothing in the public SDK surface changed. buio.tx.wait() now simply resolves faster, and the underlying aggregation is invisible to application code.

Results

Median finality across all 38 supported chains now sits at 120ms, with p99 under 400ms even during peak load. We're continuing to push this further as we onboard additional relayer regions in Q3.
