## What was built

Two DB tables (`decisions`, `decision_stages`), 8 API endpoints at `/api/decisions/...`, a decisions list page at `/decisions`, and a full 11-stage workspace at `/decisions/:id`.

## Security model

- `GET /decisions` — `requireAnyRole`; owners/supervisors see all, viewers see only their own (`createdBy`)
- `POST /decisions` — `requireAnyRole`; all roles can create
- `GET /decisions/:id` — `requireAnyRole` + `assertDecisionAccess()` (ownership check)
- `PUT /decisions/:id/stages/:stageKey` — `requireAnyRole` + ownership check (save draft)
- `POST .../ai-assist` — `requireAnyRole` + ownership check
- `POST .../validate` — **`requireSupervisorOrOwner`** + ownership + stage sequence gate
- `POST .../complete` — **`requireSupervisorOrOwner`** + ownership + stage sequence gate
- `GET .../audit` — **`requireSupervisorOrOwner`** + ownership check

## Key design rules

**Why:**
- `validate` and `complete` require supervisor/owner because viewers cannot advance constitutional decisions
- `assertDecisionAccess()` checks `createdBy === userId` for viewers; supervisors/owners bypass

## Audit hash integrity

Hash is only computed at **validation time** (never at save time). 
- `PUT /stages/:stageKey` explicitly sets `auditHash: null` on every update
- `POST .../validate` computes `SHA-256(decisionId, stageKey, stageData, userId, timestamp)` and stores it
- This means the hash represents the exact data at the moment of constitutional validation

**Why:** Pre-save hashes are meaningless since users can save multiple times before validating.

## Stage sequence enforcement

`assertCurrentStage(decision, stageKey)` enforces that validate/complete can only operate on `decision.currentStage`. Cannot skip stages.

**Why:** Constitutional lifecycle must proceed sequentially per M. Al-Shamsi Framework. Stage 9 (constitutional_validation) is the gate — it runs a comprehensive 10-principle validation.

## Case number format

`MARSAD-YYYY-NNNN` — generated by counting total rows in decisions table + 1, zero-padded to 4 digits.

## Frontend API calls

Uses direct `fetch()` with `X-User-Role` from localStorage (not generated orval hooks). Pattern:
```ts
function apiFetch(method, path, body?) {
  const role = localStorage.getItem('userRole') || 'owner';
  return fetch(path, { method, headers: { 'Content-Type': 'application/json', 'X-User-Role': role }, ... })
}
```

## Routes

- `/decisions` → decisions list page
- `/decisions/new` → workspace with create dialog open
- `/decisions/:id` → workspace for existing decision
